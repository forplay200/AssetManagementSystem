# Frontend UI 全面优化规划

日期：2026-10-08（Asia/Kuala_Lumpur）  
状态：核心前端优化已实施，验证更新于 2026-10-09；实施范围与后续项见第 11 节  
使用场景：电脑端优先，兼顾手机  
目标：保留 Aether 现有深色、紫色与蓝色风格，提高阅读效率、内容可达性与操作安全性。

## 1. 结论与边界

目前的问题集中在四个方面：长内容无统一展示规则；详情页没有明确的高度与滚动策略；不同操作的保护机制不一致；小字号、低对比度和信息层级削弱可读性。应先建立共享交互规则，再按页面接入。

第一轮优先处理：transcript 收起与全文阅读、右侧面板高度、关键操作确认、草稿保护、正文和字段标签的可读性。第二轮覆盖搜索、上传、版本、评论、团队和后台。第三轮处理数据规模与需后端支持的体验。

原规划基于当时工作区源码，包括正在开发的 3D 材质/贴图与版本功能。以下问题表保留规划时的证据与行号；后续实施已调整源码，当前交付与验证结果以第 11 节为准。非本任务的 3D 文档、素材和导出文件保持原样。

未在检查时发现 80、3000、3001、5000、5173、8080 端口的监听服务；未完成真实登录、真实数据或浏览器布局复现。因此，下表明确区分源码已确认行为与待验证的表现，不能视为完整运行时审计。

### 应保留的现有基础

已有 Skip link、路由标题/播报、页面焦点目标、reduce-motion 样式、骨架屏、空状态、权限路由、部分异步按钮禁用、文本预览大小限制、图片懒加载、Three.js 延迟加载和资源释放。应扩展这些能力。

不要把正常页面需要滚动、局部代码横向滚动或表格自身横向滚动直接判断为 bug；验收重点是内容是否可达、操作是否被遮挡、滚动是否清晰。

## 3. 视觉与阅读规范

### 配色保持

保留 `frontend/tailwind.config.js` 的六个 Aether 色值：base `#09090B`、surface `#18181B`、overlay `#27272A`、primary `#8B5CF6`、secondary `#3B82F6`、success `#10B981`。保留现有红/琥珀色的错误和警告语义；不新增主题或装饰色。

灰阶从现有 zinc 色阶中重新分配角色。正文用 zinc-200/300，辅助但必读信息用 zinc-400，zinc-600/700 不再承担字段名、操作说明、日期等可读信息。品牌、背景、渐变和圆角语言保留。

使用本地 Tailwind 颜色值计算，在不透明 surface `#18181B` 上：zinc-400 为 6.91:1，zinc-500 为 3.67:1，zinc-600 为 2.29:1，zinc-700 为 1.70:1。这是静态颜色对的计算结果；透明背景、混色、hover 与 disabled 状态仍需实测。普通文本以至少 4.5:1 为验收要求，大字至少 3:1；字体变大不能替代必要的对比度改善。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

### 字体、间距和密度

以下是项目设计目标，非 WCAG 指定字号。

| 内容 | 目标 |
| --- | --- |
| 页面标题 | 26–28px / 行高 1.3；长标题允许换行 |
| 区块标题 | 16px / 24px，Geist，清晰字重 |
| 正文、描述、transcript、评论 | 14–16px / 行高 1.6–1.75；自然语言使用 Inter |
| 字段名、按钮、表格正文 | 13–14px；手机输入框 16px |
| 辅助文字、日期、chip | 12–13px；不再使用 9–10px 传达有效信息 |
| 等宽字体 | 仅代码、ID、文件路径、技术数值；不用于整段 transcript |
| 间距 | 4/8/12/16/24/32px，块之间 20–24px，块内 12–16px |
| 操作目标 | 桌面常用按钮高 36–40px，图标有效点击区至少 32px；触屏约 44px |

关键状态有文字与图标，不只用颜色；操作名使用具体动词。保留产品当前英文语言体系，中文规划不意味着此轮引入整站翻译。

长文件名卡片最多两行，保留扩展名辨识；完整名称可通过聚焦/点击的详情入口读取与复制，不能只依赖 hover title。描述用正常断词，路径/连续无空格字符串可 `overflow-wrap:anywhere`，代码默认保留格式并提供换行开关。

## 4. 详情页、右侧面板与长文

### 推荐布局

宽屏仍保留“预览 + 信息栏”，继续使用 Details / Versions / Comments 的顶层导航，避免一次性改变用户习惯。

1. 页面标题展示完整资产名、类型、体积、工作区；主操作为下载。次要操作进入明确的菜单，删除与常用操作分组。
2. 左侧预览按文件类型分配高度。音频使用紧凑播放器，不沿用图片/3D 的 460px 占位；代码保留独立的可访问滚动区。
3. 右侧信息栏建议 360–440px，剩余宽度给预览；不足以容纳至少约 520px 预览时改为单栏。
4. 信息栏内部顺序为基本信息、可编辑 metadata、AI 状态与摘要、AI 标签、transcript、词库高级配置。标签可按类别折叠，默认显示数量。
5. 同一信息只保留一个主要编辑位置。仓库标签在预览下可做摘要，编辑集中在信息栏，避免两处长列表。

### 滚动契约

- 默认基于 xl（1280px）以上且高度充足启用双栏；以扣除导航后的真实可用宽度复核，不能只看窗口宽度。
- 桌面信息栏外层 `sticky`、`align-self:start`，最大高度由 `100dvh - stickyTop - bottomGap` 决定。顶部偏移包含现有 72px 应用头部与实际间距；标题换行与缩放时重新计算，不能给所有页面硬编码同一高度。
- 信息栏结构为标题、内容滚动区、可选编辑底栏。内容区 `min-height:0; overflow-y:auto`，父级 `min-width:0`，保存/取消始终可达。
- 右侧只设一个纵向滚动容器。transcript 展开后参与这个容器的滚动，不再套第三层滚动。可聚焦滚动区域有名称与可见焦点。
- 预览与右侧不强行等高；禁止用全页 `overflow:hidden` 掩盖内容。
- 视口高度约低于 700px、单栏或高缩放导致空间不足时，撤销侧栏锁高与吸附，恢复页面自然流。精确阈值以实施阶段 1366×768 等视口验证调整。
- 手机先显示紧凑预览，再显示分组信息；长文仍默认收起。使用正文阅读页或全屏阅读层，关闭返回原位置；避免套叠抽屉。

### 统一长文本行为

| 类型 | 默认显示 | 展开与完整内容 |
| --- | --- | --- |
| Transcript | 6 行，保留段落/换行，显示字符数量 | 展开、收起、全文阅读；全文可复制、下载 TXT、查找 |
| Summary / 描述 | 4–6 行，短文直接显示 | 超过实际行数才出现展开按钮 |
| 评论、版本说明 | 约 6 行 | 就地展开；回复上下文可定位原评论 |
| AI 标签 | 每组前 6 条，展示总数 | 显示更多/收起；长标签允许换行与全文读取 |
| 技术字段/词库 | 基本概览 | 高级内容按需展开，保留搜索或分段扩展空间 |

长文收起仅影响展示，不裁剪保存值，也不把省略号当作内容。采用渲染后的行数/高度判断溢出；窗口缩放和内容更新后重算。焦点停在切换按钮，收起时避免页面跳到不可理解的位置。

全文阅读层建议桌面宽 720–880px、正文行宽 65–80ch，顶部标题/关闭，底部复制与下载，正文滚动。API 当前只有字符串时保留原段落；不能凭空生成时间戳、说话人或字级音频同步。查找的命中应打开相应内容，不藏在折叠区。

展开偏好可按资产与区块在会话中保存。未保存的正文不持久化至普通 localStorage；不缓存用户密码、邀请凭据或敏感文件内容。

## 5. 操作保护矩阵

确认用于有实际后果的操作；低风险的频繁操作优先给反馈、待保存状态或可靠撤销。

| 操作 | 当前行为 | 规划 |
| --- | --- | --- |
| 删除资产 | 原生确认；后端同时删除当前包、历史版本及对象 | 统一危险确认，展示资产名/工作区/历史版本影响；明确无法在界面恢复；首批不加输入文件名门槛 |
| 移除成员 | 原生确认 | 展示目标、工作区和失去访问权；保留服务端最后 Owner 校验 |
| 修改角色 | 选择即提交 | 先展示旧角色 → 新角色和关键权限差异，再确认；自身降权突出提示；取消不改值 |
| Rotate code | 点击即生效 | 明确旧邀请码立即失效，现有成员不受此次码替换影响；确认后才请求，成功后更新复制状态 |
| 停用/启用系统账户 | 停用有确认，启用直接执行 | 两者均需对象确认；停用解释会话访问受阻，启用解释恢复平台访问；保留禁止停用自己 |
| 删除评论 | 已有自定义确认 | 接入共享组件，保留“隐藏正文、保留记录与回复”的真实语义 |
| 删除工作区词库概念 | 立即执行 | 工作区级确认：影响未来建议，已有资产标签保留 |
| 移除单个仓库标签 | 立即执行 | 短确认作为首批安全方案；若实现 Undo，必须真正通过接口恢复并处理失败，不能只回填 UI |
| 删除/编辑 AI 标签 | 整份 metadata 立即写入 | 改为组内草稿，显示改动数量并 Save / Cancel；首批可先明确确认删除；并发写入问题见依赖章节 |
| 删除 metadata 字段 | 删除本地行，保存后生效 | 保留草稿模式，提供行级撤销；提交前显示“将删除 N 个字段”的差异摘要 |
| 重生成 AI 结果 | 点击排队 | 已有结果时确认可能覆盖手动修改的 AI 内容；仓库标签与自定义字段的实际保留规则以 worker 行为核实；第一次生成无需额外弹窗 |
| 上传新版本/更新材质贴图 | 填表后直接保存 | 最终 Review 展示当前→新文件、附件增删、geometry-only、旧包保存与 AI 重算；确认替换后才提交 |
| 保存普通 metadata / 评论 / 快照 / 首次上传 | 明确表单提交 | 保持一次提交；显示 pending、成功/失败；删除字段或草稿离开按相应规则处理 |
| 切标签、页面、工作区、登出、取消编辑 | 不统一 | 详情内部尽量保留草稿；将丢弃草稿时弹窗，干净状态直接执行 |
| 查看、下载、预览、刷新只读结果、复制 | 直接操作 | 不加确认；下载给准备状态，复制给成功/失败反馈；刷新不得覆盖本地草稿 |

共享确认框显示明确标题、目标、影响与具体动作按钮（例如 Delete asset），默认焦点放取消。确认前不发送变更请求；执行中防重复提交；失败保留对话框和错误，允许重试。请求已发出时不把关闭视为取消服务端任务，必须保留可见的任务状态。

Dialog 必须处理焦点进入、Tab 范围、Esc、背景不可交互和关闭后的焦点返回；多个弹窗优先顺序切换，避免叠层。遵循 [W3C Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

### 草稿与上下文切换

- 草稿键包含 workspaceId、assetId、表单类型；同一详情切 tabs 时恢复草稿，切到另一资产不串数据。
- WorkspaceSwitcher 必须先询问离开，再执行 `activateTeam`，不能先改请求头中的工作区再弹确认。
- 需要丢弃时提供“继续编辑 / 放弃更改”；有有效保存能力时可加“保存并离开”，保存失败不得离开。
- 文件选择无法保证刷新后恢复；明确提示重新选文件。不自动长期存储文件二进制。
- 上传/替换进行中拦截意外离开。当前没有服务端取消接口时，不提供假“取消上传成功”。
- SPA 导航、浏览器后退、工作区切换、登出和刷新分别覆盖；beforeunload 使用浏览器原生提示且仅在 dirty/pending 时注册。不得依赖自定义刷新提示文字。
- 现有入口使用 BrowserRouter；实施前核对安装的 React Router 能力，选择统一导航协调器或必要的 router 适配，不能假定直接插入 useBlocker 即可覆盖全部场景。

## 7. 组件与技术拆分

尽量沿用 React、Tailwind、Lucide 与现有组件，不以“全面优化”为由更换框架。

| 拟建/改造的基础能力 | 职责 | 优先接入 |
| --- | --- | --- |
| 阅读与间距 tokens | 字号、行高、文字角色、点击区；保持色板 | styles、PageHeader、表单、表格 |
| Dialog / ConfirmDialog | 对话框框架、危险确认、pending/error、焦点管理 | Comments、AssetDetail、Team、System Users |
| ExpandableText / TextReader | 溢出判断、展开、原文、复制、查找、TXT | AI transcript、summary、描述、评论 |
| InspectorPanel / Section | 高度、唯一滚动区、分组、编辑底栏 | MetadataPanel；不要强套所有侧栏 |
| Draft/navigation coordinator | dirty 注册、上下文键、确认后切换、beforeunload | Metadata、Comments、Upload、Versions、WorkspaceSwitcher |
| AsyncAction / StatusNotice | 防重复、目标级 pending、保留失败输入、可访问反馈 | 所有提交与下载 |
| Tabs / Disclosure | panel 关联、方向键/Enter、展开状态、焦点 | Details、工作区 onboarding |
| Pagination / ResultState | URL 状态、loading/error/empty 互斥、结果数 | Assets、Search，再到管理与历史 |

标签导航使用 [W3C Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) 的关联与键盘行为。优先手动激活模式，避免焦点移动就触发卸载或重新请求。

MetadataPanel 目前同时承担字段编辑、AI 标签、仓库标签、长文、词库及 API 调用；按上述职责分离后再调整布局，以免加更多条件分支扩大问题。状态变更保持权限校验与现有 API 合约。

## 8. 需要区分的后端依赖

以下基础改善可纯前端完成：长文/列表折叠、字体与间距、布局与焦点、确认、草稿保护、请求序号/取消、URL 分页、准确的空态/错误态、最终提交摘要。

以下不能仅用 UI 宣称完成：

1. **AI 完整任务状态**：当前 enqueue 返回 job 信息，visual metadata 有部分 clip 状态；全类型的 queued/running/failed/completed、进度与更新时间需要核对并补齐接口。第一版只能展示可证实的“已提交/已有结果/刷新失败”等状态，不能制造百分比或“正在处理”。
2. **可靠撤销与并发编辑**：后端 `assetsController.js:444` 整体覆盖 metadata；用旧对象撤销单个标签会覆盖别人的改动。前端首批串行化同资产编辑；可靠冲突检测需 revision/ETag 或字段级更新。不能承诺整包回写即可安全 Undo。
3. **资产删除恢复**：当前 delete 会清理对象及历史，没有回收站；首批诚实告知不可恢复，回收站属于后续独立需求。
4. **版本回滚**：当前提供快照、下载、替换，不把历史快照当作现成的一键回滚能力。
5. **大列表与趋势**：团队/用户/历史分页、全库统计、跨页排序、搜索匹配上下文按后端合约实施；前端分页不等于解决传输规模。
6. **取消上传**：终止客户端等待不等于回滚服务端保存；没有取消/清理协议时仅提供离开保护和进度反馈。

## 9. 实施顺序与完成条件

阶段按依赖推进，不给未经开发估算的日期承诺。每批形成独立可审查的改动，避免一个 PR 重写整站。

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| A：基线与规范 | 建立 4 类典型资产和极端内容样本、关键页面截图；锁定色板/文字规范 | 1366×768、1920×1080、窄屏和缩放样本可复现；不依赖真实破坏性数据 |
| B：防误操作 | 共用 Dialog、角色/邀请码/资产删除保护、草稿协调；补齐现有确认的状态 | 取消零写入，确认一次请求，错误可恢复；切工作区前正确拦截 |
| C：阅读核心 | 文字 tokens、ExpandableText、详情信息栏、紧凑音频、全文阅读 | 极长 transcript 不再无限拉长默认页；右栏底部操作可达；全文无损 |
| D：全页面接入 | 搜索/列表状态与导航、上传/版本 Review、评论、团队、用户、认证文案 | 流程往返不丢状态，窄桌面无整页横向溢出，键盘可完成关键任务 |
| E：规模与依赖 | AI 状态合约、并发更新、服务端分页/统计等独立任务 | UI 与真实接口一致，不用前端模拟掩盖后端缺失 |

首批 B/C 可以共享基础组件迭代，但先完成代码已确认的内容丢失与误操作入口，再扩展视觉调整。现有 3D 开发改动必须在同一基线下复核，避免覆盖正在开发的资产包能力。
