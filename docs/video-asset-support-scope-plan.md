## 1. 已确定的目标

用户选择支持以下完整范围：

1. 视频上传与储存。
2. 浏览器播放预览。
3. 提取并显示技术 metadata。
4. 手动添加、编辑、删除标签，沿用既有资产权限。
5. 从视频抽取画面，生成视觉标签建议。
6. 用户审核、接受、修改或拒绝 AI 建议。

这是对现有数字资产管理平台的文件类型扩展。研究主线仍是资产组织、检索、权限与协作，不增加“研发完整视频理解算法”的研究承诺。

本文件取代前次讨论中的“不加入视频”作为当前目标选择；视频是否已经完成，应由实际代码、测试和部署结果另行证明。

## 2. 本阶段边界

### 纳入

- 视频列表、类型筛选、详情与当前版本预览。
- 时长、分辨率、容器/编码等可可靠获取的技术信息；帧率字段需明确含义。
- 基于已有本地 CLIP 路线的抽帧视觉标签建议、建议来源和证据时间点。
- 已审核标签参与既有检索；AI 候选是否被搜索索引采用，须与当前产品行为明确对齐，不能把未审核建议显示成已确认标签。
- 现有版本管理、角色权限、Workspace 隔离和错误处理在视频上的适用性。

### 不纳入本阶段

- 动作、事件顺序、剧情、因果关系的完整理解。
- 视频音轨的 Whisper 转录、YAMNet 声音标签及音画联合判断；原始视频正常播放音轨不受此项限制。
- 任意容器、任意编码、任意时长的通用视频平台。
- 云端视频理解 API、专门训练新视频模型、自动视频剪辑或时间轴协作。
- 自动判断著作权归属、授权有效性或侵权。
- 防录屏、DRM 或保证浏览器无法保存预览内容。

这些边界是本次范围规划，不代表相关扩展没有价值。

## 4. 推荐处理流程

```text
上传文件
  → 校验权限、大小、实际媒体格式和可处理性
  → 储存原始文件，记录 Asset/Version 与技术 metadata
  → 返回上传结果，页面显示 AI 处理状态
  → 后台抽帧并保留时间点
  → 使用已确定版本的视觉词库进行 CLIP 推理
  → 按概念汇总、去重并筛选建议
  → 用户查看画面依据并审核
  → 保存已确认标签，供资产检索使用
```

上传成功与 AI 完成是两个状态。AI 失败不应删除已成功上传的视频，也不应清空用户已有标签。

### 4.1 建议的首轮限制，尚非用户确认参数

以下只是控制实现与评估规模的候选值，必须结合实际环境测试后确定：

| 项目 | 候选方案 | 确定方式 |
| --- | --- | --- |
| 格式 | 先支持 MP4，限定经过目标浏览器验证的编码组合 | 检查实际视频流，不只检查扩展名；记录支持矩阵 |
| 大小 | 优先沿用当前主文件 50 MB 上限 | 核对所有前后端、代理与版本上传限制 |
| 时长 | 首轮以不超过 60 秒的短视频为测试范围 | 用实际处理时间和资源占用验证 |
| 抽帧 | 均匀采样，每段最多 30 帧，保留准确时间点 | 比较标签质量、耗时及短暂内容漏检 |
| 画面尺寸 | 推理前缩放；单独限制解码分辨率与资源消耗 | 在部署环境验证，不能只限制推理后的图片尺寸 |

示例采样策略可以设 `N = min(30, max(1, ceil(durationSeconds / 2)))`，在 N 个等长时间段的中点取帧。此公式是待评估方案，不是性能或准确率承诺。应记录真实解码时间戳，覆盖变帧率、极短视频和解码失败情况。

### 4.2 AI 结果要求

- 区分技术 metadata、AI 建议和用户已确认标签。
- 使用现有受控视觉词库；保留 Manager 管理共享词库的既有规则。
- 记录模型标识、词库版本、采样策略、帧时间点及汇总规则，方便复现。
- 每个候选概念可保留最高匹配分数、命中帧数量和有限数量的画面依据。
- 最终筛选阈值和跨帧汇总方式通过验证集确定，然后固定用于测试集。
- 不将原始相似度直接显示为“正确概率”；命中采样帧比例不等于概念在整段视频中的持续时间比例。
- 低证据时允许返回“未产生可靠建议”，不强制生成标签。
- 明确抽帧可能遗漏短暂内容；不声称分析了每一帧或完整理解视频。
- Regenerate 沿用确认交互，保留人工标签，清楚说明被替换的是哪一批 AI 建议。

### 4.3 可靠性与资源边界

- 后台任务设置超时、并发上限、资源限制、有限重试和临时文件清理。
- 解码工具使用参数数组调用，禁止将用户文件名拼接为 shell 命令。
- 任务绑定 Asset、文件/版本修订和任务标识；旧任务不能覆盖新版本结果。
- 删除、进入回收站或受到限制的资产不再接收过期 AI 结果。
- 手工修订与 AI 回写需避免相互覆盖。
- 当前文件及历史版本播放都应验证权限、Workspace 归属和流式读取/拖动播放行为；不能用公开下载链接绕过鉴权。
- 预览帧、封面和临时衍生文件纳入版本及清理设计，不能在源文件删除后遗留可访问副本。

## 5. 权限与 UI 约束

- Owner：管理当前 Workspace 的任何资产；日后删除治理方案若获确认，再为永久删除增加专门条件。
- Manager：只能修改自己首次上传的 Asset；更新版本不改变原始上传者归属。
- Manager 管理 Workspace 共享词库的例外保持。
- Collaborator：沿用已实施的查看、预览和评论权限，不出现下载/导出入口，下载 API 仍拒绝。
- 视频播放不授予修改或下载权限。浏览器能够接收预览内容，因此不得把“禁止产品下载入口”宣传成防复制。
- 保留现有配色；桌面优先、兼顾手机。播放器保持宽高比，侧栏限制高度并内部滚动。
- 处理状态、失败原因、重试和审核入口应可理解；不在用户流程中暴露不必要的模型实现细节。
- 证据帧与标签长列表支持折叠，不让新增内容再次导致详情侧栏无限增长。

相关既有规则见 [Manager 权限规划](asset-manager-ownership-permissions-plan.md) 和 [Collaborator 下载限制](collaborator-download-restriction-plan.md)。

## 6. 验证与完成标准

### 功能与权限

- 支持范围内视频可以上传、预览、查看 metadata、管理手动标签、搜索、更新版本。
- 错误扩展名、损坏文件、超时长/大小/分辨率、不可处理编码有明确结果。
- AI 成功、失败、无建议、重试及旧版本结果回写都有验证。
- Owner、本人 Manager、他人 Manager、Collaborator、跨 Workspace 用户分别验证。
- Collaborator 当前/历史视频预览可用，但下载入口与 API 继续受限。
- 不影响已有图片、音频、3D、脚本与数据文件流程。

### AI 与研究评估

- 使用自行制作或明确获授权的游戏相关短视频，记录来源与使用许可。
- 至少比较“单帧/封面视觉标签”和“均匀多帧标签”；不要预先宣称多帧一定更好。
- 预先定义标签相关性标注规则、precision/recall 或固定 K 的评价口径。
- 若划分调参和测试集，按原始视频/来源分组，避免同一视频的相似片段分到两边。
- 记录端到端处理耗时、失败率与关键资源占用；报告样本数量和硬件条件。
- 通过限定的视频检索任务观察标签是否帮助查找资产；SUS 单独衡量可用性，不能代替标签质量或检索耗时实验。
- 所有参数、实验与结果均按真实完成情况记录；没有实验就不能填写“已提升”的结论。
